# exp-1 agent

<img src="assets/exp-1-logo.png" alt="exp-1 logo" width="96" />

Минималистичный агент для программирования на Rust с терминальным интерфейсом, который разговаривает с **27 провайдерами**, вручая каждому список моделей, которые тот действительно обслуживает: каталог приходит на лету из models.dev, а таблица в бинарнике служит офлайн-запасным вариантом. Пять сетевых протоколов покрывают их все — API **chat-completions OpenAI**, используемый десятком поставщиков, **OpenAI Responses**, **Anthropic messages**, нативный **Gemini `generateContent`** от Vertex AI и бэкенд Codex, — а провайдер входит с API-ключом, страницей с кодом устройства, собственным входом поставщика или учётными данными, которые уже хранит машина. Путь Codex появился первым и по-прежнему остаётся одним из них: ChatGPT OAuth на `auth.openai.com`, а запросы идут на `https://chatgpt.com/backend-api/codex/responses`.

## Что он делает

- Передаёт потоком ответы эндпоинта Codex Responses (SSE, разбирается вручную).
- Выполняет цикл агента — запрос → поток → вызов инструмента → возврат вывода → повтор — пока модель не перестанет запрашивать инструменты.
- Ведёт два потока: основной разговор и побочный поток для вопросов, которые не должны его прерывать.
- Показывает рассуждения, потоковый текст ассистента, вызовы инструментов и их вывод в одном транскрипте, с длительностью каждого хода и временем на часах.

## Инструменты

| Инструмент | Аргументы | Примечания |
| --- | --- | --- |
| `read` | `path`, `limit?`, `pos?` | По умолчанию не более 400 строк; `limit` меняет это, `pos` — первая строка, счёт с 1. Вывод нумеруется, а обрезанное чтение говорит, как продолжить. Файл на 3000 строк проходится по частям намеренно: проглотить его целиком — это десятки тысяч токенов. |
| `write` | `path`, `content` | Создаёт родительские директории; перезаписывает существующий файл. |
| `edit` | `path`, `old`, `new`, `edits?` | Точная замена, всё или ничего. При неудаче называются ближайшие строки или позиции совпадений, так что несовпадение пробелов не требует повторного чтения. `edits` принимает несколько пар `{old, new}` для одного файла за один вызов. Результат показывает, что изменилось. |
| `fetch` | `url`, `limit?`, `pos?` | Одна страница обычным текстом, с постраничным просмотром, как у файла: `limit` строк (по умолчанию 400) начиная с `pos` (с 1). Скрипты и стили отбрасываются, сущности декодируются. |
| `count` | `path`, `refresh?` | Число строк в файле или во всех файлах под директорией без чтения содержимого. Кэшируется по каждому файлу в `.cache/count` с ключом по размеру и mtime. |
| `grep` | `pattern`, `path?`, `include?`, `max?` | Поиск по регулярному выражению в файле или дереве, не затягивая файлы в разговор. `include` фильтрует по имени файла (`*.rs`). Пропускает `.git`, `.cache`, `target`, `node_modules`; не ходит по симлинкам; игнорирует нетекстовые файлы. Ограничен `max` совпадениями (по умолчанию 100). |
| `delete` | `path` | Удаляет файл. Директории отклоняются — опустошение дерева относится к `shell`, где видна вся команда. |
| `shell` | `command`, `background?`, `limit?`, `output_id?` | Команда на переднем плане блокирует агента до завершения; через 60 с команда переводится в фон, и агенту сообщают, когда она завершится. `background: true` сразу возвращает id. Фоновые команды никогда не убиваются по таймеру. Вывод ограничен 30 000 байт: более длинный сохраняет начало и конец, а разрыв помечается. `output_id` перечитывает любой прошлый запуск с другим `limit`. |
| `ast` | `path?`, `refresh?` | Дерево проекта в формате `tree`. Кэшируется в `.cache/ast`; `refresh: true` перестраивает. `.git` пропускается. |
| `websearch` | `query`, `numResults?`, `type?`, `livecrawl?`, `contextMaxCharacters?` | Поиск в интернете с содержимым страниц. Использует MCP, размещённый у Exa, на `mcp.exa.ai`, которому **API-ключ не нужен**; задайте `EXA_API_KEY`, чтобы снять лимиты частоты. `type` — `auto`/`fast`/`deep`. |
| `ask_question` | `question`, `options?`, `label?`, `submit?` | Блокирует ход и показывает панель вопросов. `↑↓` выбирают вариант, `Tab` переходит между вопросами, `Enter` подтверждает, `Esc` закрывает. Всё набранное считается свободным ответом и имеет приоритет над выделенным вариантом. |

Команды оболочки выполняются от имени пользователя без песочницы. Команда на переднем плане через 60 секунд переводится в фон, фоновую команду ничто не убивает по таймеру, а вывод ограничен 30 000 байт: более длинный результат сохраняет начало и конец, а разрыв помечается как пропуск.

Инструмент `web` ищет в интернете: сначала — MCP, размещённый у Exa, потому что он возвращает содержимое страниц, а при срабатывании лимита общего бесплатного тарифа Exa — HTML-страницу DuckDuckGo. `EXA_API_KEY` переключает Exa на ваш собственный план и является единственной настройкой, нужной любому из путей.


## Платформы

Агент — одна кодовая база для Linux, macOS и Windows: TUI, цикл агента, провайдеры, MCP, навыки, сессии и встроенный titler написаны на обычном Rust и работают везде. У частей, касающихся операционной системы, есть ветка на каждую платформу:

| | Linux | macOS | Windows |
| --- | --- | --- | --- |
| TUI, агент, провайдеры, MCP, навыки, сессии | да | да | да |
| Открытие страницы входа | `xdg-open` | `open` | `cmd /C start` |
| Проверка живости демона и остановка | `kill` 0 / SIGTERM→SIGKILL | то же | `tasklist` / `taskkill /T` затем `/F` |
| Сервер, отсоединённый от своей консоли | `process_group(0)` | то же | `DETACHED_PROCESS \| CREATE_NEW_PROCESS_GROUP` |
| Директории конфигурации и состояния | `$XDG_*`, `~/.config` | `$XDG_*`, `~/.config` | `%APPDATA%`, `%LOCALAPPDATA%` |
| Картинка из буфера обмена (`ctrl + v`) | `wl-paste`, `xclip` | `pngpaste` | PowerShell + `System.Windows.Forms` |
| Уведомление о завершении хода | `notify-send` | `osascript` | Всплывающая подсказка PowerShell |
| Установки из архивов (`exp-1 install *.zip`) | `unzip` / `tar` | то же | `tar` (bsdtar читает zip) |
| Локальные MCP-серверы с именем `npx` | как написано | как написано | повторяется как `npx.cmd` |

Ветки демона и буфера обмена для Unix и Windows были проверены компиляцией путём их временного включения на Linux; `creation_flags` — единственный вызов, существующий только для Windows, который нельзя проверить без цели Windows, и ничто из этого ещё не запускалось на настоящей машине с Windows или macOS.

### Кросс-сборка из Linux

Бинарник для Windows собирается на Arch с помощью цепочки инструментов mingw (для этого один раз нужны права root):

```sh
sudo pacman -S --needed mingw-w64-binutils mingw-w64-gcc
rustup target add x86_64-pc-windows-gnu
cargo build --release --target x86_64-pc-windows-gnu
```

Именно `dlltool` из `mingw-w64-binutils` нужен библиотекам импорта; без него сборка останавливается на `windows-sys`.

Без root тот же бинарник получается из архива llvm-mingw, распакованного в `~/.local`. Стандартная библиотека Rust для этой цели просит у компоновщика `libgcc.a`, которой llvm-mingw не поставляет, поэтому двойная симлинк-прослойка предоставляет эквиваленты, а `--no-default-features` отключает встроенный titler, как это делает CI:

```sh
mkdir -p ~/.local/mingw-shim
ln -sf ~/.local/llvm-mingw/lib/clang/*/lib/windows/libclang_rt.builtins-x86_64.a ~/.local/mingw-shim/libgcc.a
ln -sf ~/.local/llvm-mingw/x86_64-w64-mingw32/lib/libunwind.a ~/.local/mingw-shim/libgcc_eh.a
PATH="$HOME/.local/mingw-shim:$HOME/.local/llvm-mingw/bin:$PATH" \
CARGO_TARGET_X86_64_PC_WINDOWS_GNU_LINKER="$HOME/.local/llvm-mingw/bin/x86_64-w64-mingw32-clang" \
RUSTFLAGS="-L $HOME/.local/mingw-shim" \
cargo build --release --target x86_64-pc-windows-gnu --no-default-features
```

`cargo` и `rustup` из `~/.cargo/bin` знают о кросс-целях; системные пакеты — нет, а на этой машине `~/.cargo/bin` отсутствует в `PATH`, так что вызывайте их по полному пути.

Бинарнику для macOS root тоже не нужен, и с `cargo zigbuild` всё дерево собирается под `aarch64-apple-darwin`: `zig cc` кросс-компилирует C-зависимости (включая `aws-lc-sys`, чего не может обычный `cargo check` — хостовый `cc` отвергает `-arch arm64`), и каждый крейт компилируется. Останавливает всё последний шаг: фича `rustls` в `reqwest` 0.13 подтягивает `rustls-platform-verifier`, и компоновщик сообщает `unable to find framework 'Security'` и `'CoreFoundation'`. Они есть только в Apple SDK; Zig преспокойно компонует Mach-O и libSystem, но фреймворки не поставляет. Поэтому бинарники для macOS берутся с Mac или из CI (`.github/workflows/release.yml` собирает обе архитектуры). Рецепт ниже — тот, что доходит до компоновки:

```sh
mkdir -p ~/.local/zig && curl -L https://ziglang.org/download/0.14.1/zig-x86_64-linux-0.14.1.tar.xz \
  | tar -xJ -C ~/.local/zig --strip-components=1
cargo install cargo-zigbuild
rustup target add aarch64-apple-darwin
PATH="$HOME/.local/zig:$PATH" cargo zigbuild --release --target aarch64-apple-darwin
```

Результат не подписан. На Apple Silicon неподписанный бинарник убивается при запуске, поэтому его нужно один раз подписать на самом Mac:

```sh
codesign -s - --force ./exp1-agent        # ad-hoc signature
xattr -cr ./exp1-agent                    # if it arrived by download
```

## Требования

- Rust 1.85+ (edition 2024)
- Либо уже существующий вход в Codex CLI (его `auth.json` переиспользуется), либо `/login`, который сам выполняет ту же процедуру device flow.
- Встроенный титлер, скомпилированный в агент из `src/titler.rs` под фичей `titler`. Он подтягивает Candle, из-за чего первая сборка занимает время, а бинарник весит ~16 МБ, а не ~7 МБ. Как только веса окажутся в кэше Hugging Face, генерация заголовков идёт офлайн.

## Установка

Для установки последней версии с GitHub нужны Rust 1.85+ и Cargo:

```sh
cargo install --git https://github.com/archpulse/exp-1.git --locked exp1-agent
exp1-agent --help
```

Cargo устанавливает бинарник `exp1-agent` в `~/.cargo/bin`; при необходимости добавьте этот каталог в `PATH`. В стандартную сборку входит локальный титлер, поэтому первая установка занимает больше времени, пока собирается Candle.

## Использование

```sh
cargo run --release                      # uses the current directory
exp1-agent --model gpt-6-luna --effort high # pick a model and reasoning effort
exp1-agent --cwd ~/projects/my-app          # run the shell tool somewhere else
exp1-agent --help
```

| Клавиша | Действие |
| --- | --- |
| `Enter` | Отправить промпт или выполнить команду, когда она уже дописана |
| `↑` `↓` | Переместить выделение автодополнения или вызвать прошлые промпты |
| `Tab` | Принять выделенное автодополнение |
| `Ctrl + /` | Переключиться между основным и побочным потоками |
| `Ctrl + Shift + A` | Переключить режим разрешений: always ask → never ask → ask only commands |
| `Esc` | Сам по себе — ничего |
| `Esc` `Esc` | Прервать выполняющийся ход либо закрыть список автодополнения или панель выбора |
| `Ctrl-C` | Выйти |
| `Ctrl-U` | Очистить строку ввода |
| `Ctrl-Backspace` | Удалить предыдущее слово |
| `Ctrl-Delete` | Удалить следующее слово |
| `Ctrl-W`, `Alt-Backspace` | То же, что `Ctrl-Backspace` |
| Колесо мыши | Прокрутить транскрипт |
| `PgUp` / `PgDn` | Прокрутить транскрипт |
| `←` `→` `Home` `End` | Переместить курсор |
| `Backspace` / `Delete` | Редактирование |

Стрелки ходят по истории промптов: отправив `hi`, нажатие `↑` возвращает его в поле, следующие нажатия уходят дальше назад, а `↓` идёт вперёд до пустого поля. Прокрутка — на колесе мыши, поэтому стрелки свободны для истории.

Ввод `/` открывает список автодополнения с фильтром по префиксу. После пробела дополняются и аргументы команды — `/themes <tab>` перечисляет схемы, `/model <tab>` — модели, а `/model gpt-6-luna <tab>` — уровни усилий. `Enter` на голых `/model` или `/themes` открывает вместо этого нумерованный список выбора; `/model` — два шага: сначала модель, потом уровень усилий. При пустом поле курсор стоит в самом начале, перед заполнителем.

Строка подсказки меняется по контексту. Пока выполняется ход, ввод заблокирован.

`Esc` намеренно бездействует; прерывает двойное нажатие. Прерывание отменяет запрос в полёте и отбрасывает частичный текст ассистента, оставляя историю разговора целой.

Доступные темы: `default` (синий), `amber`, `jade`, `mono`. Цвета — truecolor, поэтому тема терминала не может их переопределить.

## Интерфейс

Раскладка повторяет TUI OpenAI Codex: никаких панелей с рамками, шапка `>_` с рабочей директорией под ней, всплывающее окно автодополнения или нумерованная панель выбора над вводом, полоса ввода с отступами, приглашением `›` и мигающим курсором `│`, затем строка модели и строка подсказки.

- Отправленный промпт отрисовывается обратно в транскрипте полосой во всю ширину, как это делает Codex.
- **Вывод инструментов по умолчанию скрыт**: в транскрипте остаётся вызов (`read src/main.rs`), а не то, что он вернул. `ctrl-o` показывает вывод под его вызовом и прячет обратно — это и есть разница между тем, чтобы следить за работой, и тем, чтобы её вычитывать.
- **Мышь — не только для прокрутки.** Колесо прокручивает, перетаскивание выделяет и копирует, а клик действует на то, по чему попал: строка панели выбора или окна автодополнения ведёт себя как Enter на этой строке, подсказка `ctrl + / for side` в нижней строке переключает потоки, а ссылка в сообщении открывается в браузере. Каждый кадр записывает нарисованные им области, поэтому клик — это проверка попадания по последнему кадру, а не догадка о раскладке. Подсветка при наведении намеренно не сделана: она стоит перерисовки на каждом движении мыши, а собственный курсор терминала и так показывает, где указатель.
- Субагент сообщает о текущем шаге **одной обновляющейся строкой** (`subagent → grep tokenizer`), а не строкой на каждый шаг, а вызвавший его вызов читается как `task: <description>`.
- **Клик по вашему собственному сообщению спрашивает, что с ним делать**, а не делает это: маленькое меню с `copy` (текст уходит в буфер обмена) и `revert`. Откат отбрасывает всё после этого сообщения — разговор, то, что было сказано модели после этой точки, и все изменения файлов, сделанные последующими ходами, которые возвращает журнал отмены. Само сообщение уходит из транскрипта, а его текст возвращается в промпт, чтобы его можно было отредактировать и отправить снова. Текст проверяется до того, как что-либо выбрасывается, поэтому клик, попавший не по тому сообщению, ничего не делает.
- Транскрипт прижат к новейшему сообщению; колесо мыши или `PageUp`/`PageDown` прокручивают вверх по истории, `ctrl-g` возвращает к новейшему сообщению, а `ctrl-t` — к старейшему, и вид, прокрученный вверх, остаётся на месте, пока приходят новые строки, вместо того чтобы его тянуло вниз.
- Перетаскивание мышью выделяет текст в любом месте экрана — включая шапку — и при отпускании отправляет его в буфер обмена: сначала OSC 52, так что это работает и по ssh, затем `wl-copy`, `xclip` или `xsel`, если они есть. Заметка `copied N chars` подтверждает это в строке подсказки. Выделение — приглушённая подсветка за текстом, которая останавливается на последнем символе каждой строки, как ведёт себя собственное выделение терминала. Терминал никогда не видит перетаскивания, потому что приложение держит мышь для прокрутки, так что это единственный способ скопировать.
- Прикреплённая картинка показывается заполненной плашкой `Image 1` над промптом, а рядом — `ctrl-v replaces it`, так что то, что вот-вот отправится, видно прямо в полосе ввода.
- Пока ход выполняется, строка активности сидит **прямо под промптом, которому принадлежит**, — со своей меткой для каждого действия: `⠋ thinking 4s`, пока запрос в полёте, `⠋ preparing write… (12 KB) 8s`, пока модель всё ещё пишет аргументы вызова инструмента, `⠋ running 4s`, пока инструмент выполняется. У каждой метки свои часы, поэтому секунды относятся к тому, что происходит сейчас, и никогда не считают весь ход; общий итог хода сообщает `Worked for` в конце. Нижняя строка остаётся простой меткой `GPT-6-Luna high · /path · <thread> · Main [default]`; `esc esc interrupts` живёт в строке подсказки.
- После завершения хода в транскрипт добавляется `Worked for 5s · 12:08 PM`.
- Строка модели читается как `GPT-6-Luna high · /path · <thread name> · Main [default]` или `… · Agent` в побочном потоке. Имя потока берётся из первого промпта.
- Строка подсказки несёт переключатель потока справа, красным, когда активен побочный поток.
- Пустой экран остаётся тихим: полный список команд появляется только на машине, которая ещё ни разу не сохраняла разговор, а после этого это одна строка, указывающая на `/` и `/help`.
- Ввод остаётся живым во время хода, так что вопрос через `/btw` можно задать не дожидаясь.
- `/btw` или `ctrl + /` отвечает в побочном чате, который несёт весь основной разговор как контекст, ничего к нему не добавляя.
- `shift + tab` переключает между режимами build и plan; в нижней строке, пока он включён, отображается `plan mode`.
- Ход, длящийся дольше пятнадцати секунд, даёт звонок терминала (и дёргает `notify-send`, где он есть на рабочем столе), когда завершается, чтобы за долгой работой не приходилось следить.
- `shift + enter` вставляет перевод строки вместо отправки, так что промпт может быть в несколько строк; полоса ввода растёт, чтобы их уместить.
- `ctrl + v` берёт картинку из буфера обмена (Wayland — `wl-paste`, X11 — `xclip`) и прикрепляет её к следующему промпту, показывая `▣ image attached` в строке подсказки, пока она не отправлена. Картинка путешествует как data URL, так что бэкенды Codex, OpenAI, Anthropic и Gemini все передают её дальше.
- `ask_question` поднимает панель над вводом, повторяя инструмент Question: акцентная полоса по левому краю, заголовок `Questions`, вкладки, когда вопросы задаются вместе, нумерованные варианты с выделенным, слот `Type your own answer` и `⇥tab ↑↓ select enter confirm esc dismiss` внизу.

Цвета — truecolor, поэтому тема терминала не может их переопределить. Модель, уровень усилий и тема переключаются на ходу через `/model` и `/themes`.

Намеренные отличия от Codex: у Codex есть `/permissions` и `/review`, которым нужны политика песочницы и рецензент диффов; в этой сборке вместо них `/clear` и `/help`. Нижняя строка Codex рекламирует оверлеи агента и сочетаний клавиш, которых в этом MVP нет.

## Аутентификация

`/login` выводит список провайдеров, и вход в каждый устроен так, как ожидает его поставщик:

- **API-ключ** для большинства из них, отправляемый как `Authorization: Bearer` (или `x-api-key` для API Anthropic) и хранимый по провайдерам в `~/.config/exp-1/credentials.json` с правами `0600`. Один ключ может покрывать несколько провайдеров — `opencode-go` и `opencode-zen` — один аккаунт за двумя базовыми URL, а `providers::key_group` называет группы.
- **Вход по коду устройства** для `openai (auth)`, `github copilot` и `meta (auth)`: в браузере открывается страница входа поставщика, а URL и код печатаются как запасной вариант.
- **Токен из собственного входа поставщика** для `anthropic (auth)`, отправляемый с заголовками идентичности официального клиента.
- **Учётные данные, которые машина уже хранит**, для `google vertex`: то, что настроил `gcloud auth application-default login`, причём `GOOGLE_CLOUD_PROJECT` и `GOOGLE_CLOUD_LOCATION` называют проект и регион. Вставлять ничего не нужно.

Путь Codex вдобавок ведёт собственный файл: при первом запуске агент копирует `$CODEX_HOME/auth.json` (по умолчанию `~/.codex/auth.json`) в `~/.exp1-agent/auth.json` и работает с этой копией. **Ваши настоящие учётные данные Codex никогда не перезаписываются.** Когда токену доступа остаётся 5 минут до истечения, агент обновляет его:

```
POST https://auth.openai.com/oauth/token
grant_type=refresh_token
client_id=app_EMoamEEZ73f0CkXaXp7hrann
```

В ответ приходит новый токен обновления, и он записывается обратно в собственную копию агента. Хранимый файл записывается атомарно с правами `0600`.

## Модели и уровни усилий

Ни список моделей, ни уровни усилий не зашиты в код. И то и другое читается из собственного каталога Codex CLI в `$CODEX_HOME/models_cache.json` (по умолчанию `~/.codex/models_cache.json`) с использованием `slug`, `display_name`, `description`, `visibility`, `default_reasoning_level` и `supported_reasoning_levels` каждой записи. При запуске по умолчанию берётся первая указанная модель этого каталога.

**Все остальные провайдеры получают свой список на лету, из models.dev.** Каталог загружается не чаще раза в двенадцать часов в `~/.cache/exp-1/models-dev.json`, держится в памяти и читается ради трёх вещей: id моделей, которые предлагает провайдер, протокол каждой модели (models.dev записывает его как пакет AI SDK, с которым настроен провайдер, — `@ai-sdk/anthropic` для модели Claude за шлюзом, `@ai-sdk/openai` для Grok) и контекстное окно, из которого вычисляется порог автоматического сжатия. Провайдер, отсутствующий в каталоге, сохраняет таблицу в `src/providers.rs`, как и машина без сети, так что приложение никогда не зависит от загрузки.

Модель, которой нет в таблицах вовсе, всё равно получает протокол: его решает префикс поставщика (`claude-*`, `minimax-*` и `qwen-*` говорят на Anthropic, `grok-*`, `gpt-*` и `muse-*` — на Responses, `gemini-*` — на Gemini, всё остальное — chat), а провайдер, говорящий на одном протоколе везде, отвечает за всё остальное.

**Панель выбора показывает всех провайдеров, где выполнен вход**, одной полкой, а не по одной на каждый вход: строки несут `via <provider>`, чтобы различать две шляпы на одном имени модели, провайдер в работе идёт первым, а выбор модели у другого провайдера сначала переключает на него, а затем ставит модель. Такую длинную полку ищут набором: каждая панель фильтруется по мере набора, backspace расширяет совпадение, а Escape расширяет его, прежде чем закрыться. Область в `/scoped-models` фильтрует ту же полку и называет модель одного провайдера (`opencode-go/grok-4.7`), так что одно имя от двух провайдеров — это две записи; старая область с голыми именами по-прежнему означает «это имя, от любого провайдера», а `ctrl-a` в этой панели очищает область, и снова предлагается всё. `/model grok-4.7` берёт провайдера в работе, когда имя предлагают несколько, а `/model opencode-go/grok-4.7` называет одного точно.

Уровни усилий действительно различаются от модели к модели, поэтому угадывать их не работает:

| Модель | Уровни усилий |
| --- | --- |
| `gpt-5.6-terra` | low, medium, high, xhigh, max, **ultra** |
| `gpt-6-luna` | low, medium, high, xhigh, max |
| `gpt-5.5` | low, medium, high, xhigh |

Панель выбора уровня усилий, автодополнение `/model <name> <tab>` и валидация — все следуют за активной моделью. При переключении моделей уровень усилий переносится, когда новая модель его принимает, иначе берётся `default_reasoning_level` этой модели, так что запросить у модели уровень усилий, которого у неё нет, невозможно:

```
/model gpt-5.6-terra ultra   →  GPT-5.6-Terra ultra
/model gpt-5.5               →  GPT-5.5 medium          (ultra is not a gpt-5.5 level)
/model gpt-5.5 max           →  'max' is not a GPT-5.5 level;
                                this model takes low, medium, high, xhigh
```

В панели выбора появляются только модели с `visibility: "list"`; скрытые остаются доступны по имени. Если файл каталога отсутствует, приложение переходит на консервативный встроенный список, чтобы оставаться работоспособным, и говорит об этом в панели выбора.

Отвечать будут только те модели, на которые у вошедшего аккаунта ChatGPT есть право, — остальные бэкенд отклоняет с поясняющей ошибкой.

## Отрисовка

Ответы ассистента рисуются как rich text внутри процесса. Внешнего рендерера нет — ни `pandoc`, ни бинарника TeX, ни растеризации изображений; всё происходит внутри TUI, так что стоит почти ничего.

- **Markdown**: заголовки, жирный, курсив, встроенный код, блоки кода с полосой слева и меткой языка, маркированные и нумерованные списки, цитаты, горизонтальные линии, ссылки, таблицы с вертикальными чертами в стиле GitHub, разложенные рамками из символов псевдографики с выравниванием по столбцам, и встроенная математика `$…$`.
- **Математика LaTeX**: символы и отношения, греческий алфавит, `\frac`, `\sqrt`, нижние и верхние индексы, `\mathbb` и `\mathcal`, комбинирующиеся диакритические знаки (`\bar`, `\hat`, `\vec`, …), прямые имена операторов (`\log`, `\sin`, `\lim`, …) и выключные блоки `$$…$$`.

Всё, что конвертер не узнаёт, выводится дословно, вместе со скобками, чтобы незнакомый ввод оставался читаемым, а не превращался в кашу. Это конвертер, а не движок TeX: макросы, окружения вроде `tikz` и многострочные раскладки не интерпретируются.

Markdown разбирается **один раз**, когда приходит сообщение, на не зависящие от темы отрезки; отрисовка лишь сопоставляет эти отрезки цветам. Поэтому переключение темы ничего не переразбирает.

Замерено на собранном бинарнике: **~1 % одного ядра в простое** с мигающим курсором, ~3 % при быстрой прокрутке колесом.

## Субагенты и длинные команды

**Субагенты.** Инструмент `task` запускает второго агента с собственным контекстом и теми же инструментами, а затем возвращает только его отчёт — полезно для работы, которая иначе затопила бы контекст вызывающего. Отчёт обрезается до 6 000 символов, потому что попадает в контекст вызывающего, а транскрипт показывает его прогресс одной строкой, которая заменяется на каждом шаге, а не строкой на каждый шаг. Вложенные субагенты доступны, пока остаётся глубина, но не глубже двух уровней, чтобы рекурсия не убежала. Транскрипт показывает каждый шаг субагента.

**Медленные команды переводятся в фон, а не убиваются.** Команда на переднем плане, всё ещё работающая спустя **60 секунд**, переезжает в фон, и агенту об этом сообщают, вместо того чтобы блокировать ход:

```
'sleep 75' is still running after 60s, so it was moved to the background as 'bg-1'.
Carry on; you will be told when it finishes, or poll it with {"output_id": "bg-1"}.
```

**Завершение прерывает.** Когда фоновая команда заканчивается, выполняющийся ход прерывается и агенту отдают вывод, так что результат никогда не теряется молча за долгой работой:

```
• interrupted: a background command finished
```

## Диктовка

Кнопка микрофона в нижнем углу (`ctrl-r` делает то же самое) надиктовывает текст в промпт: нажмите её, говорите, нажмите ещё раз. Текст приходит по мере речи, потому что распознаватель работает потоком, а на кнопке, пока она слушает, идёт таймер.

Распознаватель — **whistle**, локальный движок речи от Cactus, запускаемый как `whistle --mic`. Именно этот режим и делает его потоковым: он записывает сырое моно 16 кГц из `pw-record` от pipewire по секунде за раз, прогоняет каждую секунду через потоковый декодер и печатает по одной строке JSON на каждое обновление (`text` — то, что зафиксировано, `pending` — то, что ещё в пути). Перевод строки на его stdin завершает поток и сбрасывает хвост. Команда, язык, слова-подсказки и источник звука берутся из окружения:

Рекордер — родной для платформы: `pw-record` (pipewire) на Linux, `ffmpeg` с avfoundation на macOS, `ffmpeg` с dshow на Windows (`WHISTLE_SOURCE` выбирает входное устройство, `WHISTLE_RECORDER` заменяет команду целиком). Само приложение только запускает `EXP1_DICTATE --mic` и читает его строки JSON, так что подойдёт любой распознаватель, работающий потоком так же; без него нажатие кнопки микрофона скажет об этом в нижней строке, и больше ничего не произойдёт.

```sh
EXP1_DICTATE=/path/to/whistle     # default: whistle on PATH
EXP1_DICTATE_LANG=en              # default: whatever it detects
EXP1_DICTATE_KEYWORDS=country,Americans
WHISTLE_SOURCE=…                  # default: the system's own input
```

Диктовка есть только на Linux, потому что только там есть рекордер; остальной агент — нет.

Этот режим есть только в этой копии whistle: логика лежит в его библиотеке типом `Dictation` (`start`, `next`, `finish`), а его `main.rs` — тонкий цикл над ней. У whistle здесь нет собственного репозитория, поэтому свежей копии от его автора придётся заново применить эти два файла или указать `EXP1_DICTATE` на что-то, говорящее на том же протоколе. Распознаватель, не знающий `--mic`, не игнорируется: он скажет об этом своими словами в нижней строке.

## Провайдеры

`/login` открывает панель выбора провайдеров; `/scoped-models` решает, какие из их моделей предлагает `/model` (пусто — все, и область хранится в `settings.json`). Панель — простой алфавитный список, а курсор открывается на провайдере в работе, так что искать позицию не приходится. Выбор провайдера, где вход уже выполнен, переключает на него и говорит об этом; выбор того, который уже в работе, — или запуск `/login <id>` — намеренно выполняет вход заново. Вход по коду устройства открывает в браузере страницу поставщика и печатает URL и код как запасной вариант.

**Один ключ может покрывать несколько провайдеров.** `opencode-go` и `opencode-zen` — один аккаунт за двумя базовыми URL, поэтому вход в любой из них сохраняет ключ для обоих (`providers::key_group` называет группы). Шлюзы opencode к тому же маршрутизируют по сессии: каждый запрос несёт `x-opencode-session`, `x-opencode-project` и `x-opencode-client`, без которых шлюз отказывает наотрез («Request is missing x-opencode-session»).

Пять сетевых протоколов покрывают всё реализованное здесь: **chat-completions OpenAI**, используемый десятком поставщиков, **OpenAI Responses**, **Anthropic messages**, нативный **Gemini `generateContent`** от Vertex AI и **бэкенд Codex**, с которым говорит `openai (auth)`. Все передают SSE и декодируются в тот же поток событий, который создаёт клиент Codex, так что цикл агента не знает, с кем говорит.

| opencode-go | `opencode.ai/zen/go/v1` | Responses + Anthropic + OpenAI |
| anthropic (auth) | `api.anthropic.com/v1` | Anthropic |
| google vertex | `aiplatform.googleapis.com/v1` | Gemini |
| gitlab-duo | `cloud.gitlab.com/ai/v1/proxy/anthropic/v1` | Anthropic |

Каждая запись реализована: модель сама называет протокол, на котором отвечает, так что шлюз вроде `opencode-go` может обслуживать три сразу. Список и базовые URL взяты из [models.dev](https://models.dev), публичного реестра, который читает сам opencode, а не из догадок.

Каждый базовый URL выше был проверен заведомо недействительным ключом: отказ доказывает, что URL и заголовок аутентификации верны. Все двадцать семь ответили `400`, `401` или `403` — кроме `fireworks-ai`, чей `404` — это его собственное `"Model not found"` с идентификатором запроса `chatcmpl-`, так что даже тот запрос дошёл до маршрута инференса. `google vertex` отвечает `401` на своём пути с проектом.

## Режимы

`shift + tab` переключает сессию между двумя режимами, и нижняя строка говорит, какой активен:

- **build** — всё так, как описано здесь.
- **plan** — инструменты, меняющие файлы (`write`, `edit`, `delete`), отклоняются *и* исключаются из списка инструментов, так что модель исследует и предлагает план вместо редактирования. От `shell` ожидается, что он останется только для чтения. Формулировка живёт в `prompts/plan.md` и редактируется, как и всё остальное.

## Разрешения

`~/.config/exp-1/permissions.json` — список исключений; вызов, не совпавший ни с одним правилом, выполняется. Решает первое совпадение:

```json
{
  "rules": [
    { "action": "shell", "resource": "rm -rf *", "effect": "deny" },
    { "action": "write", "resource": "/etc/*", "effect": "ask" },
    { "action": "fetch", "resource": "*", "effect": "allow" }
  ]
}
```

`action` — имя инструмента или `*`, `resource` — то, к чему обращается вызов (путь для файловых инструментов, командная строка для `shell`, URL или запрос для сетевых), а `*`/`?` работают как подстановочные знаки. `effect` — `allow`, `ask` или `deny`. `ask` поднимает панель вопросов и держит вызов, пока не будет ответа (две минуты, затем вызов отклоняется). Правила действуют и на субагентов.

`ctrl + shift + a` переключает режим разрешений: **always ask** (по умолчанию для свежей установки) заставляет `write`, `edit`, `delete` и `shell` поднимать вопрос, **never ask** выполняет их без вопроса, а **ask only commands** спрашивает только за `shell`. Инструменты только для чтения не спрашивают никогда, а правило с `effect: deny` отказывает в любом режиме — режим никогда не отменяет запрет.

## Инструкции проекта

`AGENTS.md` читается из рабочей директории и каждого родителя над ней, начиная с самого верхнего, и добавляется к системному промпту — так собственные правила репозитория доходят до модели, не вставляясь в разговор. `/init` записывает стартовый файл.

## Сбои провайдеров

Сбой на стороне сервера или транспорта повторяется один раз через две секунды; отклонённый запрос (4xx) — нет. Когда основная модель продолжает сбоить, `fallback_model` в `settings.json` называет модель того же провайдера, которую пробуют один раз, прежде чем сдаться, и переключение отмечается в транскрипте.

## Навыки

Навык — это директория с `SKILL.md` внутри, той же формы, что используют Claude Code и opencode. Установка делает его командой:

```sh
exp-1 install ~/skills/pdf-tools          # a directory with SKILL.md
exp-1 install notes.md                    # a single markdown file
exp-1 install tools.zip                   # an archive (unzip or tar)
exp-1 install https://example.com/skill.md
```

Файлы попадают в `~/.config/exp-1/skills/<name>/`, имя берётся из поля `name:` фронтматтера, когда оно есть, и из имени файла или директории иначе. Установленные навыки появляются рядом со встроенными командами во всплывающем окне автодополнения и в справке пустого экрана, а `/<name>` запускает один из них: сервер читает инструкции навыка, записывает их в разговор как задачу и позволяет модели им следовать. `description:` из фронтматтера показывает панель выбора.

## MCP-серверы

Инструменты с серверов [MCP](https://modelcontextprotocol.io) предлагаются модели наравне со встроенными. Список живёт в `~/.config/exp-1/mcp.json`, ровно той формы, что использует opencode, так что запись можно переносить между ними:

```json
{
  "mcp": {
    "context7": { "type": "remote", "url": "https://mcp.context7.com/mcp" },
    "blender": {
      "type": "local",
      "command": ["blender-mcp"],
      "environment": { "BLENDER_HOST": "localhost" }
    }
  }
}
```

- Серверы `local` запускаются, и разговор с ними идёт по stdio; до `remote` достаются по HTTP, с ответом в JSON или SSE. `"disabled": true` пропускает сервер, не удаляя его, а `"headers"` добавляет то, что нужно удалённому серверу.
- Инструменты доходят до модели как `<server>_<tool>`, обе половины проходят такую же очистку, как в opencode (`context7_resolve-library-id`), так что два сервера никогда не столкнутся.
- Серверы подключаются **в фоне** при запуске: медленный или мёртвый не задерживает агента, и о нём сообщается, а не забывается — `/mcp` перечисляет каждый сервер с числом его инструментов или ошибкой, с которой он упал.

## Фоновый сервер

Смоделирован по демону opencode. **Обычный запуск `exp1-agent` поднимает сервер и присоединяется к нему**, ровно как команда opencode по умолчанию берёт `daemon.transport()` и передаёт её интерфейсу.

Следствие и есть суть: закрытие интерфейса оставляет сервер работать, так что следующий запуск переиспользует тёплый процесс. Сервер переиспользуется, только когда у него **и** та же версия, **и** та же сборка: `server.json` записывает размер и время модификации исполняемого файла, поэтому клиент, пересобранный после старта сервера, заменяет его, вместо того чтобы говорить на протоколе, которого сервер больше не знает. Замерено на этой машине:

| | холодный запуск | следующий запуск |
| --- | --- | --- |
| Порождение UI → первый кадр | 189 ms | **84 ms** |
| RSS UI | 14.4 MB | 16.0 MB |
| RSS сервера | 15.2 MB | 20.5 MB (после хода) |

Замерено ещё раз с пятью открытыми сессиями сразу:

| | один сервер + 5 UI | пять отдельных процессов |
| --- | --- | --- |
| простой | 97 MB (15 + 5 × 16) | 183 MB (5 × 37) |
| со встроенным titler | 143 MB | 423 MB (5 × 85) |

Сервер ленив в том, что загружает: клиент Codex появляется на первом ходу (+5 MB), а встроенный titler — только если заголовок действительно генерируется локально (+48 MB, поэтому `auto` предпочитает модель). Эта лень и есть почти весь смысл — 48 MB весов платятся один раз на каждую сессию на машине, а не один раз на процесс.

Дорогое состояние в расчёте на машину — реестр инструментов и модель titler на ~49 MB — живёт в единственном сервере, а клиент Codex строится в первый раз, когда он понадобится для запроса по протоколу Codex, так что машина, вошедшая в любого другого провайдера, поднимает сервер без учётных данных Codex. Каждый UI — тонкий клиент, поэтому N параллельных сессий стоят `1 x 63 MB + N x 15 MB` вместо `N x 61 MB`, и только первый запуск платит за холодный старт.

```sh
exp1-agent serve                 # run the server in the foreground
exp1-agent service start         # spawn it detached (survives the launcher)
exp1-agent service status        # pid, url, version, health
exp1-agent service stop          # SIGTERM, then SIGKILL after a grace period
exp1-agent service restart
exp1-agent service password      # print, or set with an argument
```

- **Регистрация**: `~/.local/state/exp-1/server.json` хранит `{id, version, url, pid}`. Клиент читает его, проверяет `/health` с таймаутом 2 с и переиспользует сервер, только когда совпадает ещё и версия — устаревший или чужой сервер сначала останавливается.
- **Пароль**: `~/.local/state/exp-1/password`, 32 случайных байта, права `0600`, сохраняются между перезапусками, чтобы заново запущенный клиент переподключался, ничего не зная.
- **Отсоединённый запуск**: `exp1-agent serve --register` в собственной группе процессов с закрытыми стандартными потоками, так что он переживает любого клиента, который его запустил.

### HTTP API

Все маршруты требуют `Authorization: Bearer <password>`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/health` | живость и версия |
| `GET` | `/sessions` | список живых сессий |
| `POST` | `/sessions` | создать одну; `x-exp1-directory` задаёт её рабочую директорию |
| `GET` | `/sessions/{id}` | полный снимок |
| `POST` | `/sessions/{id}/prompt` | начать ход |
| `GET` | `/sessions/{id}/events` | SSE: snapshot, deltas, tools, usage, title, done, idle |
| `POST` | `/sessions/{id}/answer` | ответить на ожидающий `ask_question` |
| `POST` | `/sessions/{id}/interrupt` | прервать выполняющийся ход |
| `GET` | `/models` | каталог с реальными уровнями усилий каждой модели. `?all=1` игнорирует область: панели, которая задаёт область, нужны и модели вне неё |

Сессия несёт собственную рабочую директорию, так что один сервер обслуживает несколько проектов; директория приходит с `POST /sessions`, а не фиксируется при запуске сервера.

## Автосжатие

Длинный разговор суммируется, прежде чем переполнить контекстное окно. После каждого хода сервер сравнивает `input_tokens` запроса с `context_window` модели из каталога Codex и сжимает разговор, как только он достигает **95 %**:

```
Context at 7378 of 258400 tokens (95% threshold) — compacting
Conversation compacted; continuing from the summary
```

Сжатие отправляет разговор модели с промптом для суммирования и структурированным шаблоном, который использует opencode — Objective, Important Details, Work State (Completed / Active / Blocked), Next Move, Relevant Files, — а выводы инструментов обрезаются до 2000 символов, чтобы не утопить суммаризатор.

Переписанный разговор — это **сводка, за которой следуют последние пять пользовательских ходов, сохранённые дословно**, каждый со своими вызовами инструментов агента и их результатами, чтобы текущая нить не потерялась:

```
[user]      Summary of everything so far: ## Objective …
[user]      Turn two: run shell ["seq","1","900"] and reply OK.
[call]      shell
[result]    exit_code: 0 1 2 3 …
[assistant] OK
… four more turns …
```

Факт, названный до сжатия, остаётся известным и после него. Если один из этих ходов сам по себе огромен, старейшие записи хвоста отбрасываются, пока результат снова не уложится в окно, так что один гигантский вывод инструмента не может заставить разговор сжиматься бесконечно.

Долю можно задать через `EXP1_COMPACT_PERCENT`, если хочется другой, — это же и способ прогнать этот путь, не заполняя окно на 272 000 токенов.

Разговор держит на диске до 5 000 сообщений транскрипта; собственный контекст модели ограничивается отдельно обрезкой и сжатием, так что долгая сессия остаётся читаемой, не тратя токены.

## Хранение данных

Конфигурация живёт в `~/.config/exp-1/` (или `$XDG_CONFIG_HOME/exp-1`); сами разговоры — в `~/.cache/exp-1/sessions/` (или `$XDG_CACHE_HOME/exp-1/sessions`), потому что транскрипт — это кэш: потерять его стоит контекста, а не настройки. Собственные файлы демона — `server.json` и `password` — лежат в `~/.local/state/exp-1/`.

| Файл | Что хранит |
| --- | --- |
| `config/settings.json` | модель, уровень усилий, тема, режим titler, запасная модель |
| `config/credentials.json` | один API-ключ на провайдера, права `0600` |
| `config/prompts/*.md` | системные промпты, редактируемые: `system`, `subagent`, `compaction`, `title`, `plan` |
| `config/permissions.json` | правила allow/ask/deny |
| `config/mcp.json` | MCP-серверы |
| `config/skills/` | установленные навыки, по директории на каждый |
| `cache/sessions/<id>.json` | один разговор: заголовок, оба транскрипта, история со стороны модели, история промптов |

Разговор держит на диске свои новейшие **250 сообщений**, а весь кэш при старте сервера подрезается до **250 MB** — самые старые файлы первыми. Старая раскладка, где всё лежало в `config/exp-1/sessions/`, мигрирует при первом запуске после изменения.

Настройки записываются при выходе приложения; сессия записывается после каждого завершённого хода, так что сбой стоит максимум хода в полёте.

Встроенный titler — необязательная фича: `cargo build --release --no-default-features` исключает его и уносит с собой всю зависимость Candle, и тогда заголовки сессий берутся только у модели. CI собирает именно так, потому что titler подтягивает Candle: крейт лежит в дереве, но релизу не приходится за него платить.

Промпты — это файлы, а не константы: `~/.config/exp-1/prompts/system.md` (собственные инструкции агента), `subagent.md`, `compaction.md` и `title.md` записываются при первом запуске и читаются на каждом запросе, так что правка применяется к следующему ходу без пересборки. Порядок разрешения модели и уровня усилий при запуске: **командная строка → сохранённые настройки → первая указанная модель каталога**.

**Каждый запуск начинается с пустой сессии.** Ничего не возобновляется автоматически — `/sessions` открывает панель выбора сохранённых разговоров, новейшие первыми, каждый со своим сгенерированным заголовком, id и временем последнего использования. Список ограничен директорией: сессия видна там, где она была начата, везде ниже этого, и повсюду, если она была начата в `$HOME` (такие сессии — «глобальные»). Сам `$HOME` перечисляет только глобальные, чтобы не превращаться в каталог всех проектов. Выбор одной сохраняет разговор, который вы покидаете, и загружает выбранный. `/clear` бросает текущий разговор и начинает свежий, сохраняя ваши настройки.

### Заголовки сессий

Заголовки приходят от встроенного **titler** — локальной T5 (7,6 млн параметров, 3 слоя энкодера и 3 декодера), которая работает через Candle в этом же процессе и скомпилирована в агент из `src/titler.rs`. Веса (`Cyronius/titler`) читаются из кэша Hugging Face и загружаются не более одного раза на процесс, так что, оказавшись на диске, генерация заголовков становится локальной, мгновенной и бесплатной.

Генерация идёт в блокирующем потоке в момент завершения первого хода и никогда — в потоке UI. Сессии с родителем — побочный чат — не называются вовсе, так как принадлежат разговору, за которым следуют. Используется многоязычный путь библиотеки (не сырой), поэтому язык определяется, а неанглийский промпт сначала переводится на английский. Сессия называется один раз, а предпросмотр, взятый из промпта, показывает панель выбора, пока заголовок не пришёл.

**Кто называет сессию — это настройка**, `titler` в `settings.json`:

| Значение | Поведение |
| --- | --- |
| `auto` (по умолчанию) | сначала модель Codex, встроенный titler — как запасной |
| `local` | только встроенный titler — без трат на API, заголовки слабее |
| `remote` | только модель Codex |

Заголовки запрашивают у дешёвого уровня `luna` каталога, а не у собственной модели сессии — та же идея, что opencode, спрашивающий у провайдера его маленькую модель, — и токены, потраченные на заголовок, прибавляются к расходу сессии, как любой другой вызов.

`/retitle` заново называет сессию — на этот раз по исходному запросу плюс недавний разговор (ограничен 8 000 символов) — так opencode заново генерирует заголовок, когда сессию переименовывают в пустое имя. Сам промпт живёт в `prompts/title.md` и представляет собой полный документ в стиле opencode: задача, правила (тот же язык, что у пользователя, ≤50 символов, сохранять точные термины и числа, никогда не отвечать на вопрос) и десять разобранных примеров.

`auto` намеренно ведёт с модели Codex. Titler на 7,6 млн честен насчёт своего размера: на тех же русских промптах он выдал `Understanding Two Plus Terms` для «сколько будет два плюс два» и `Request for Sign` для запроса таблички, потому что бесплатный переводчик Google передаёт «табличку» как "sign", и маленькая модель озаглавливает уже перевод. Модель Codex называет те же промпты `Сколько будет два плюс два?` и `Формула корней квадратного уравнения в LaTeX`. Этот путь через LLM и есть то, для чего нужен `prompts/title.md`, — встроенная модель берёт первое сообщение как есть и полностью игнорирует файл.

## Ограничения

Ход выполняется не более чем за 200 раундов работы инструментов; если он до них дойдёт, транскрипт скажет об этом, а не остановится молча.

**Экономия токенов.** Запросы намеренно остаются маленькими: `read` листает страницами, `grep` ограничивает совпадения, длинный вывод команды сохраняет оба конца, отчёт субагента обрезается до 6 000 символов, а перед каждым запросом старейшие выводы инструментов — за пределами последних двух ходов — заменяются однострочной заметкой о том, что было отброшено. Модель может заново запустить инструмент ради всего, что ей ещё нужно, а транскрипт, который видит пользователь, сохраняет полный текст.

**Параллельные вызовы.** Сообщение модели может запрашивать несколько инструментов сразу. Серии вызовов только для чтения (`read`, `grep`, `count`, `ast`, `fetch`, `websearch`) выполняются одновременно; всё, что пишет, сохраняет свой порядок, так что запись и следующее за ней чтение того же файла не могут поменяться местами.

Это MVP. Известные пробелы:

- Vertex принимает только учётные данные application-default от gcloud; ключ сервисной учётной записи, которому нужен подписанный JWT, не выпускается.
- Побочный чат видит весь основной разговор при каждом вопросе — основная история читается, но никогда не пишется, — так что ответ `/btw` имеет полный контекст, а основной поток остаётся нетронутым.
- Потоковой отмены сверх прерывания задачи нет.
- Команды выполняются без песочницы.
